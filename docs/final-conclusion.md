# 최초 두 방식의 실행·검토 자료 비교 결과

후속으로 기존 mesh replay를 벗어나 [새 합성 원본의 PNG 기반 복원 실험](synthetic-conclusion.md)을 실행했다. 그 결과와 한계는 별도 기록을 따른다.

실행일: 2026-10-15. 원래 정한 개별 정밀 처리와 그룹 처리만 비교했다. 처리 단위와 검토 보드 축소가 서로 섞이지 않도록 두 요인의 교차 조건을 추가했으며, 새로운 모델링 방식이나 저비용 agent 실험은 추가하지 않았다.

## 결론

1. **이미 정해진 대칭 형상은 그룹 적용으로 유지할 수 있었다.** 발 외피 4개에서 모든 조건의 world vertex 차이는 0m, topology/material/smooth 배정도 같았다. 그러나 형상 적용 자체는 약 5~7ms여서 그룹 적용이 전체 작업 시간을 줄인다는 근거는 얻지 못했다.
2. **이번 실행에서 절약된 시간은 대부분 검토 렌더 수를 줄인 결과였다.** 32회 렌더의 중앙값은 약 8.1초, 원래 지정한 3뷰는 약 1.0초였다. 개별/그룹 처리 방식을 고정한 비교에서도 같은 경향이었다. 절약은 약 7초이며 전체 모델링 시간 절약률이 아니다.
3. **3장 검토를 쓴다면 원본 40% overlay·조립 사선·대표 확대 구성을 지켜야 한다.** 단순히 그룹 전체를 세 방향에서 찍는 구성과 다르다. 처음 pilot의 정면·사선·아래 그룹 3뷰는 이 규격과 달라 최종 수치에서 제외했다. 최종 3뷰는 대표 FL 원본 overlay용 정면, 실제 로봇 전체의 접합 문맥 사선, 대표 FL 확대 사선으로 다시 실행했다. 아래/뒷면/다른 파츠의 결함 검출률까지 동등하다고 판정하지 않았다.
4. **원본 해석과 승인 절차를 줄여도 된다는 결론은 없다.** 이번은 기존 형상 replay이며 새 이미지 추출·독립 3D 모델링·사람의 검토/수정/승인을 실행한 비교가 아니다. 따라서 최초 승인율, 재수정, token 비용이나 원본 일치 정확도에 대해서는 판정을 보류한다.

실무 적용 권고는 **원본 분석과 검증을 유지하고, 승인된 반복 배치만 그룹으로 처리**하는 것이다. 검토는 원래 정한 overlay·접합·확대 3장으로 시작하되, 가려진 면이나 불확실한 부분의 기존 상세 검토를 생략하지 않는다. 이 권고를 근거로 모델을 자동 채택하거나 승인 기록을 바꾸지 않았다.

## 실제 실행

- 고정 입력: 채택 ear v02, 미채택 legs v11에서 읽은 기존 발 외피, 동일 A01 원본/점 revision. 입력 hash를 매 조건 뒤 재검사했다.
- A: 네 발 각각의 저장된 vertex/face를 적용. B: FL 외피와 X/Y 대칭 규칙을 공유. 범위는 외피 4개뿐이며 다른 다리·발가락·커프를 수정하지 않았다.
- 8방향: 외피 하나씩 8뷰, 총 32회 렌더. 3뷰: overlay용 대표 정면, 전체 조립 사선, 대표 확대. 40% overlay 조판은 별도 후처리이며 그 시간도 별도로 기록했다. 8방향 조건에도 같은 대표 원본 overlay를 생성했다.
- 조건당 3회, 총 12개 후보. 2회차는 실행 순서를 뒤집었다. 각 조건은 새 Blender process에서 같은 baseline을 열었고 CPU 자원 경합을 피하기 위해 순차 실행했다.
- Blender 5.2.2 LTS, Cycles CPU, 640×640, 12 samples, 최대 8 threads. 외부 파일 autoexec 비활성화.

| 처리 | 검토 구성 | 형상 적용 중앙값 | 렌더 중앙값 | 시작·로드·저장 포함 process 중앙값 |
|---|---|---:|---:|---:|
| 개별 A | 개별 8방향 | 0.005326초 | 8.157368초 | 9.842334초 |
| 그룹 B | 개별 8방향 | 0.007008초 | 8.126605초 | 9.887146초 |
| 개별 A | 원래 3뷰 | 0.006053초 | 0.961386초 | 2.669743초 |
| 그룹 B | 원래 3뷰 | 0.005822초 | 0.977931초 | 2.660627초 |

전체 process 값은 overlay 후처리와 재개방 검사 시간은 제외한다. overlay 조판 중앙값은 조건별 약 0.05~0.06초였다. 표의 시간에는 AI 분석·코드 작성·사용자 대기가 없다. 표본이 작아 통계적 일반화나 밀리초 수준의 우열을 주장하지 않는다.

## 검증 결과

- 12개 후보 모두 새 process에서 재개방, 보호된 180개 scene object fingerprint와 전체 material fingerprint/object 목록 검사 통과.
- 네 외피의 evaluated mesh boundary/zero-area/winding 충돌 검사 모두 통과. editable mesh는 single-user 유지.
- 전체 조건 간 최대 world vertex 차이 0m. 같은 camera의 대표 정면 렌더도 최대 pixel channel 차이 0으로 동일했다.
- 채택 blend, v11 blend, recipe, 원본 이미지/점 JSON, state/contract의 hash 변경 없음. 원본 폴더에 승인·모델 수정 없음.
- 기본 offline 테스트 4개 재실행 통과.
- 설정 준비 중 조립 문맥에 Curve가 포함된 경우 mesh vertices 접근이 실패했다. 공통 object bound_box로 framing을 수정하고 최종 12개를 같은 script revision으로 처음부터 실행했다. 실패한 준비 실행과 이전 pilot은 최종 집계에서 제외했다.

Overlay는 원본과 모델의 너비를 균일 배율로 맞추고 bbox 중심을 이동한 **진단용 비교**다. camera는 독립 보정되지 않았으며 source가 약한 3/4뷰다. overlay 잔차를 모델 오차로 인증하거나 이를 줄이려고 설계를 임의 변형하지 않았다.

## 산출물과 종료 상태

[측정 JSON](../results/final-comparison.json), `run_experiment.py`, `experiment.py`에 실행/검사 과정이 있다. 로컬 `paw-workflow-final-03`에 12개 후보·렌더·overlay·로그·재개방 결과를 보존했다. 이 저장소에는 코드와 측정 결과만 올렸다.

처음 정한 두 방식의 **자동 실행 및 검토 자료 생성 비교는 종료**했다. 기존 형상 replay를 새 원본부터의 전체 pipeline 비교로 확대 해석하지 않는다. 사람 검토 시간·재수정·token은 미측정이며 미채택 후보를 production 모델로 승격하지 않았다. 추가 방식이나 설계 변경은 도입하지 않았다.
